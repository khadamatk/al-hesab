# SRS - Software Requirements Specification

## عَ الحساب - Money Management MVP

مشتقة من `BRD.md` و`USER_STORIES.md`. أرقام المتطلبات ثابتة وتُستخدم في الاختبارات والتتبع.

---

## 1. المتطلبات الوظيفية

### FR-1 - المساحات المالية

- FR-1.1: إنشاء وإعادة تسمية وأرشفة مساحة من نوع شخصي أو فريلانس أو شركة أو أخرى.
- FR-1.2: كل حساب وفئة وحركة وميزانية ودين يتبع مساحة واحدة.
- FR-1.3: الفلاتر والتقارير لا تخلط المساحات افتراضيًا.
- FR-1.4: النقل بين مساحتين ينشئ حركتين مرتبطتين ومصنفتين، ولا يُسجل كتحويل داخلي محايد.

### FR-2 - العملات والحسابات

- FR-2.1: إدارة عملات بكود ورمز و`decimal_digits` من 0 إلى 3، مع منع تغيير المنازل بعد وجود حركات.
- FR-2.2: إدارة حسابات من نوع cash أو bank أو mobile_wallet أو paypal أو other داخل مساحة.
- FR-2.3: إضافة جيب عملة واحد أو أكثر للحساب مع منع تكرار `(account_id, currency_code)`.
- FR-2.4: الرصيد الافتتاحي يسجل كحركة opening balance، والرصيد الحالي يساوي مجموع قيود الجيب.
- FR-2.5: الحساب أو الجيب المستخدم تاريخيًا يُؤرشف ولا يُحذف بطريقة تكسر السجل.
- FR-2.6: PayPal يمكن أن يحتوي جيوب عملات متعددة مستقلة.

### FR-3 - الفئات والأطراف والقنوات

- FR-3.1: الفئة إما income أو expense وتتبع مساحة؛ يمنع تكرار الاسم داخل النوع والمساحة بدون اعتبار حالة الأحرف.
- FR-3.2: حذف فئة مستخدمة يتطلب إعادة ربط الحركات بفئة بديلة من النوع نفسه داخل transaction.
- FR-3.3: إدارة أطراف مثل عميل أو مورد أو مُقرض أو مدين لاستخدامها في الحركات والديون.
- FR-3.4: إدارة قنوات مثل InstaPay وATM وbank transfer وPayPal وmanual.
- FR-3.5: InstaPay لا يملك رصيدًا؛ يرتبط بحسابات بنكية، والحركة تحدد البنك المستخدم.

### FR-4 - الدخل والمصروف والتسويات

- FR-4.1: تسجيل دخل موجب إلى جيب حساب مع فئة دخل وتاريخ وطرف/قناة/ملاحظة اختيارية.
- FR-4.2: تسجيل مصروف موجب من جيب حساب مع فئة مصروف، مع منع العملية إذا لم يُسمح بالرصيد السالب وكان الرصيد غير كافٍ.
- FR-4.3: تعديل أو حذف حركة يعيد حساب الأرصدة والميزانيات المرتبطة داخل transaction.
- FR-4.4: التسوية اليدوية تسجل كحركة adjustment بسبب إلزامي؛ لا يعدل الرصيد مباشرة.
- FR-4.5: كل مبلغ يُحوّل إلى integer minor units وفق عملته قبل الحفظ.

### FR-5 - التحويلات والرسوم والعملات

- FR-5.1: تحويل نفس العملة داخل المساحة ينشئ قيدًا سالبًا للمصدر وموجبًا للمستلم بالقيمة نفسها داخل transaction واحدة.
- FR-5.2: التحويل لا يظهر كدخل أو مصروف؛ الرسوم حركة مصروف منفصلة مرتبطة بالتحويل.
- FR-5.3: سحب ATM هو تحويل من bank pocket إلى cash pocket؛ العمولة فقط مصروف.
- FR-5.4: التحويل العابر للعملات يحفظ مبلغ/عملة المصدر ومبلغ/عملة الوجهة الفعليين، ويمنع ترك أي منهما فارغًا أو صفرًا.
- FR-5.5: لا يجلب النظام سعر صرف ولا يملأ قيمة تلقائيًا؛ يمكن عرض effective rate مشتق غير مخزن كحقيقة مستقلة.
- FR-5.6: الإرسال لطرف خارجي يسجل كدفعة/مصروف/سداد وليس كتحويل إلى حساب وهمي يملكه المستخدم.
- FR-5.7: لو استلم الطرف الخارجي عملة مختلفة، يحفظ النظام قيمة المصدر وقيمة تسوية الطرف حتى بدون destination account مملوك للمستخدم.

### FR-6 - الديون والمستحقات

- FR-6.1: إنشاء التزام `payable` أو `receivable` بعملة واحدة وطرف ومبلغ أصل موجب وتاريخ واستحقاق اختياريين، ونوع `loan`, `credit_purchase`, `invoice`, `money_lent`, أو `other`.
- FR-6.2: استلام قرض يمكن أن ينشئ دينًا وحركة داخلة إلى حساب من غير تصنيفها دخلًا.
- FR-6.3: سداد دين ينشئ حركة خارجة ويربط دفعة بالدين؛ تحصيل مستحق ينشئ حركة داخلة ويربطها بالمستحق.
- FR-6.4: يدعم النظام دفعات جزئية، ويحسب المتبقي من الأصل ناقص الدفعات ولا يسمح بتجاوزه.
- FR-6.5: الحالة open أو partial أو settled أو cancelled مشتقة/مقيدة بما يحفظ التاريخ؛ الإلغاء يحتاج سببًا ولا يحذف الدفعات.
- FR-6.6: تقارير الـMVP cash basis: تحصيل invoice دخل، وسداد credit_purchase مصروف؛ أصل loan أو money_lent وتمويله/استرداده لا يدخل في الدخل أو المصروف، والفائدة/الرسوم مصروف منفصل.

### FR-7 - الميزانيات والتنبيهات

- FR-7.1: الميزانية شهرية لكل `(workspace, currency, category?)`؛ `category = NULL` تعني حدًا عامًا.
- FR-7.2: الميزانيات تعتمد على حركات expense فقط، ولا تشمل التحويلات أو أصل الدين أو الدخل.
- FR-7.3: تنبيه قابل للتهيئة افتراضيًا عند 80% وتنبيه تجاوز عند 100%، مرة واحدة لكل مستوى وميزانية شهرية.
- FR-7.4: تعديل/حذف المصروف يعيد الحساب؛ لا يمحو سجل تنبيه سبق إرساله.
- FR-7.5: بدء شهر جديد ينسخ أحدث حدود سابقة كسجلات جديدة من غير تعديل التاريخ.

### FR-8 - التقارير

- FR-8.1: عرض الرصيد لكل حساب وجيب عملة ومساحة.
- FR-8.2: تقارير الدخل والمصروف وصافي التدفق حسب المساحة والفترة والعملة والفئة والحساب.
- FR-8.3: تقرير الديون والمستحقات والمتبقي والاستحقاقات والمدفوعات.
- FR-8.4: العملات لا تُجمع في رقم مالي واحد؛ تُعرض أقسام منفصلة.
- FR-8.5: التحويلات الداخلية لا تضخم الدخل أو المصروف.

### FR-9 - التشغيل المحلي

- FR-9.1: كل الوظائف السابقة تعمل من SQLite محلية بدون شبكة.
- FR-9.2: جميع العمليات متعددة الصفوف تستخدم transaction مع `PRAGMA foreign_keys = ON`.

## 2. المتطلبات غير الوظيفية

| # | المتطلب | التفصيل |
| :---- | :---- | :---- |
| NFR-1 | الأداء | حفظ حركة محلية معتادة في أقل من ثانية |
| NFR-2 | Offline | 100% من وظائف MVP بلا إنترنت |
| NFR-3 | سهولة الإدخال | دخل/مصروف معتاد في 4-5 لمسات وأقل من 10 ثوانٍ |
| NFR-4 | التوافق | Android 8+ وiOS 13+ |
| NFR-5 | سلامة الأموال | integer minor units فقط؛ ممنوع `double` للحفظ والتجميع |
| NFR-6 | قابلية المراجعة | لا تعديل مباشر للرصيد؛ كل تغيير له حركة ووقت وسبب |
| NFR-7 | الاتساق | القيود وعمليات repository تمنع الحركة الناقصة أو الدفعة الزائدة |
| NFR-8 | التعريب | العربية المصرية وRTL أساسيان، والكود بالمصطلحات الإنجليزية |
| NFR-9 | الخصوصية | لا تُرسل البيانات المالية أو أسماء الأطراف خارج الجهاز |
| NFR-10 | الاستعادة | صيغة backup/restore تُحسم وتُختبر قبل التوزيع |
| NFR-11 | الوصول | تكبير النص والتباين وsemantics بدون قص الوظائف الأساسية |
| NFR-12 | التطور | schema versioning ومهاجرات forward-only مختبرة |

## 3. خارج النطاق الحالي

- استيراد بنكي تلقائي CSV/SMS/API.
- أسعار صرف حية أو تحويل آلي.
- AI insights.
- Sync/Auth/Backend.
- محاسبة ضريبية أو فواتير قانونية أو دفتر أستاذ تجاري معتمد.
