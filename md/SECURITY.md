# SECURITY.md — قائمة يقظة أمنية

> قرار 1.3.0: تم تعطيل Android Auto Backup وFull Backup، ومنع Cleartext Traffic. النسخ الاحتياطي المتاح هو النسخ المحلي اليدوي المُدار والمفحوص داخل التطبيق.

**حد واضح:** دي نقطة بداية تأسيسية وليست بديلاً عن threat modeling أو مراجعة الكود والتبعيات قبل الإصدار. الأرصدة والحركات وأسماء الأطراف والديون بيانات مالية شخصية/مهنية حساسة حتى لو لم تتضمن بيانات دخول بنكية.

## Checklist قبل أي Build/Release

### البيانات المحلية

- [x] قاعدة SQLite داخل Application Sandbox وليست Public Storage.
- [x] منع طباعة المبالغ والملاحظات أو مسار قاعدة البيانات في production logs وcrash reports.
- [x] منع طباعة أسماء الحسابات والأطراف وأرصدة الجيوب والديون في production logs وanalytics.
- [x] استبعاد كل نطاقات البيانات من Android Cloud Backup وDevice Transfer صراحة، مع تعطيل Auto Backup.
- [ ] لو تقرر تشفير قاعدة البيانات، تُستخدم قاعدة مشفرة مناسبة مثل SQLCipher؛ مفتاح التشفير فقط يُحفظ في Keychain/Keystore عبر `flutter_secure_storage`. المكتبة ليست مخزنًا لقاعدة البيانات نفسها.
- [ ] اختبار فقدان/تغيير مفتاح التشفير، الترقية، والاستعادة قبل تفعيل التشفير للمستخدمين.
- [ ] أي export محلي مستقبلي يوضح أن الملف يحتوي بيانات مالية، ولا يُترك تلقائياً في public storage من غير اختيار صريح.

### الأسرار والمفاتيح

- [x] لا يوجد API key حساس داخل كود التطبيق أو assets أو `.env`. ملفات `.env` في تطبيق موبايل تساعد في فصل الإعدادات فقط ولا تمنع استخراج القيم من APK/IPA.
- [ ] أي خدمة مستقبلية تحتاج secret حقيقي تمر عبر backend/proxy موثوق؛ التطبيق يحمل public configuration فقط.
- [ ] ملفات البيئة المحلية ومفاتيح signing لا تُرفع إلى source control. راجع `.gitignore` الموجود في جذر المشروع.

### الصلاحيات

- [x] لا يطلب إصدار 1.3.0 أي صلاحية حساسة أو إنترنت؛ فحص APK أثبت عدم وجود Camera/Storage/Contacts/Location/Internet.
- [ ] رفض الإشعارات لا يعطل التطبيق؛ حالة الميزانية تظل ظاهرة داخله.
- [ ] قراءة SMS مؤجلة وتحتاج مراجعة منفصلة لسياسات Google Play وApp Store والخصوصية قبل أي تنفيذ.

### سلامة البيانات والمدخلات

- [x] كل استعلامات SQLite التي تتلقى مدخل المستخدم parameterized.
- [x] المبلغ موجب ويُحوّل إلى integer minor units؛ لا يُحفظ المال باستخدام floating-point.
- [x] تفعيل `PRAGMA foreign_keys = ON` لكل اتصال ومغطى بالاختبارات.
- [ ] الاسم والملاحظة والرمز لها حدود طول معقولة، والتحقق من كود اللون وكود العملة.
- [ ] لا يُحفظ رقم بطاقة/حساب كامل أو CVV أو PIN أو بيانات دخول PayPal/InstaPay؛ `identifier_hint` وصف أو آخر 4 أرقام فقط.
- [ ] الرصيد مشتق من ledger منشور؛ ممنوع تعديل current balance مباشرة أو حذف حركة مالية posted بلا void/reversal موثق.
- [ ] عمليات التحويل والرسوم والديون/الدفعات وإعادة ربط الفئات ونسخ الميزانية atomic داخل transaction.
- [ ] اختبارات تمنع نقل حركة أو pocket بين workspaces بطريقة تخلط بيانات الشخصي والفريلانس والشركة.

### التوزيع وسلسلة التوريد

- [x] مفاتيح signing و`key.properties` وملفات keystore مستبعدة من المصدر؛ APK موقع RSA 3072 وSignature v2.
- [ ] تثبيت إصدارات dependencies ومراجعة تحديثاتها وتراخيصها والثغرات المعروفة قبل الإصدار.
- [ ] تعطيل debug flags والـverbose logging في release build.
- [ ] لو التوزيع Side-loading، توثيق مصدر الملف ووسيلة التحقق منه للمستقبلين.

## بوابة إصدار 1.3.0 — 2026-08-13

- لا توجد صلاحيات Android حساسة ولا صلاحية إنترنت في APK النهائي.
- Cleartext Traffic ممنوع في الـManifest وفي Network Security Config، والثقة مقصورة على شهادات النظام.
- Android Auto Backup وCloud Backup وDevice Transfer مستبعد منها root/files/database/shared preferences/external.
- النسخة Release مبنية مع Dart obfuscation؛ ملفات فك الرموز محفوظة محليًا في `releases/1.3.0/symbols` ولا تُوزع.
- SHA-256 للـAPK النهائي: `4AF9F2098092FB9400443B1BFDAE88DD6443ED4D1E9DCF608E450CA8B1E3C47B`.
- المتبقي كتحسين اختياري وليس مانع إصدار: قفل بالبصمة/رمز، منع لقطات الشاشة، وتشفير مستقل لقاعدة البيانات. هذه تغيّر تجربة الاستخدام وإدارة المفاتيح وتحتاج مرحلة واختبارات استعادة منفصلة.

## لو اتضاف Backend/Sync

يُعاد عمل threat model يغطي الهوية والصلاحيات لكل سجل، TLS، تخزين tokens، rate limiting، إدارة الأسرار، تشفير النقل، التعارضات، الحذف، وسياسة الخصوصية. إضافة backend ليست امتداداً صغيراً لقائمة الـMVP الحالية.
